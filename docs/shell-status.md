## Two defects found and fixed this turn, neither subject to ITERATION_CAP (A-13)

1. **Directions link tap target.** `rendertruth.mjs` flagged the `Get directions` link at
   92x21 on `/` and `/contact` at 390. The A-14 rule covers `tel:` links only, by design -
   it is deliberately not a blanket rule, because `min-height` on every inline link would
   move the type scale the diff measures. The directions link is a control, not prose, so
   it got the 44px box explicitly in `app/shell.css`.
2. **A stale server serving a rebuilt `.next`.** After the CSS fix, `pnpm start` failed
   with the port already held by the previous process, and the still-running old server
   was serving a stylesheet hash that no longer existed. `rendertruth.mjs` then reported
   17 tap-target findings that were in fact one finding: **the page had no CSS at all.**
   Nothing was wrong with the markup. The tell was `"RRidge Garage Door Repair"` in a
   finding - the logo mark and the wordmark with no styling between them.

   **The operational rule, written down because it will recur:** after any rebuild, kill
   whatever holds the port and start a fresh server, then re-verify identity AND that the
   stylesheet the HTML references returns 200, before believing a gate:

       curl -s http://127.0.0.1:3104/ | grep -o '<title>[^<]*</title>'
       CSS=$(curl -s http://127.0.0.1:3104/ | grep -o '/_next/static/css/[^"]*\.css' | head -1)
       curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:3104$CSS"

   A gate run against an unstyled page reports real numbers about a page nobody will ever
   see, and every one of them looks like a content defect.

## What is built, and what is deliberately not

Built and frozen (A-6 - no section agent edits any of these):

- `app/globals.css` - the token set and the applied palette, plus the A-14 rule, the
  two-layer focus ring, the four `data-surface` bands and the reduced-motion baseline.
- `app/shell.css` - header, drawer, footer, call bar, map, stub styles.
- `app/layout.tsx` - Mulish + Inter via `next/font`, metadata, JSON-LD mount.
- `components/SiteHeader.tsx` - static bar, five-route nav, always-visible `tel:` CTA at
  >=768, hamburger below it, drawer per `docs/behavior/01`.
- `components/SiteFooter.tsx` - NAP, hours, SERVICE_AREA, five route links. No email
  column and no licence number: the reference footer carries both and we carry neither
  (D-03, D-14).
- `components/CallBar.tsx` - sticky call bar below 768 per `docs/behavior/03`.
- `components/BusinessMap.tsx` - coords-only keyless embed, lazy, titled, aspect-ratio
  wrapper, directions link, zoom as a prop.
- `components/LocalBusinessJsonLd.tsx` - built from `lib/business.ts`. No email, no
  aggregateRating, no review, no priceRange, no areaServed array.
- `lib/business.ts` - the typed accessor every component reads. It re-exports `site` from
  `content/copy.ts` rather than retyping the literals, because the Prompt 3 similarity
  gate imports `content/copy.ts` with a bare Node `import()` and cannot resolve the `@/`
  alias, so the dependency has to point that way round. There is exactly one place each
  business fact is written.
- Five route stubs, each with its Prompt 3 meta title and description and a
  `data-section` identity.

Deliberately NOT built this turn: every content section in `docs/sections.md`. They land
in the build wave.
